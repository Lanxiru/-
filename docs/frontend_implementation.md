# 前端可操作网页界面实施方案

本文档说明如何把当前提示词包升级为用户可操作的网页界面。仓库中已提供一个无需构建工具的静态原型：`web/index.html`。

## 1. 推荐产品形态

网页界面建议分为三块：

1. **资料输入区**：任务书、基地背景、规划指标、设计偏好、现状图上传。
2. **智能体工作区**：对话、阶段选择、方案生成按钮、规范自检、图像提示词输出。
3. **成果区**：方案摘要、表格、图像提示词、生成图片或图片历史记录。

## 2. 最小前端原型

当前仓库的 `web/` 目录提供了一个静态原型：

```text
web/index.html   # 页面结构
web/styles.css   # 页面样式
web/app.js       # 表单整理、示例填充、图片预览、请求生成
```

运行方式：

```bash
./scripts/start_web.sh
```

如果不用脚本，也可以运行：

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory web
```

然后在浏览器打开：

```text
http://localhost:8000
```

如果浏览器提示 `ERR_CONNECTION_REFUSED`，请确认启动命令仍在运行，并在容器或远程环境中使用端口转发地址；详细排查见 `web/README.md`。

这个原型目前不会直接调用模型，而是把用户输入整理成一段结构化请求，方便后续发送给后端。

## 3. 为什么不建议前端直接调用模型

不要把大模型 API Key 写在前端代码里，因为浏览器代码会暴露给用户。推荐架构是：

```text
浏览器前端
  ↓ HTTPS
你的后端 API
  ↓ 安全读取 API Key
文本模型 / 多模态视觉模型 / 图像生成模型
```

后端应负责：

- 读取系统提示词和知识文件。
- 接收任务书文字与图片。
- 调用文本模型、多模态视觉模型或图像生成模型。
- 返回结构化结果给前端。
- 记录对话历史和方案版本。

## 4. 前端页面流程

建议前端按以下步骤组织交互：

1. 用户填写任务书和基地背景。
2. 用户上传现状图，并手动补充保留要素与限制条件。
3. 用户选择当前阶段，例如“任务解析、现状诊断、概念方案、图像提示词”。
4. 前端生成结构化请求。
5. 后端调用 AI 模型并返回结果。
6. 前端用卡片、表格、Markdown 和图片预览展示结果。
7. 用户选择一个方案继续深化。

## 5. 后端 API 建议

可以先做三个接口：

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/chat` | `POST` | 发送文字任务书、当前阶段和对话历史，返回方案文本 |
| `/api/analyze-image` | `POST` | 上传现状图，返回图像要素摘要和待确认问题 |
| `/api/generate-image` | `POST` | 发送最终图像提示词，返回生成图片地址 |

`/api/chat` 请求体示例：

```json
{
  "stage": "概念方案",
  "project": {
    "name": "滨水老厂区更新设计",
    "site_context": "某城市中心区滨水老厂区，约 12 公顷",
    "brief": "保留两栋厂房，导入社区服务、创意办公、商业和滨水公园",
    "constraints": "南侧水岸不可改变，北侧设置主要入口"
  },
  "requested_output": ["方案比较", "规范风险", "图像提示词"]
}
```

## 6. 后续可升级功能

- 登录与项目管理：保存多个课程设计项目。
- 多轮对话：保留每轮方案修改记录。
- 现状图标注：用户在图上画红线、入口、保留建筑和噪声源。
- 方案版本对比：对比 A/B/C 方案的指标、优缺点和图面表达。
- Markdown 导出：一键导出汇报文本、任务书解析和提示词。
- 图片历史：保存每次生成的鸟瞰、轴测、节点图和对应提示词。
- GIS/CAD 扩展：后续接入矢量边界、面积测算和图层管理。

## 7. 技术选型建议

| 复杂度 | 前端 | 后端 | 适用情况 |
| --- | --- | --- | --- |
| 低 | 静态 HTML/CSS/JS | 无或轻量函数 | 课程展示、交互原型 |
| 中 | React / Vue / Svelte | Node.js / Python FastAPI | 需要真实模型调用和项目保存 |
| 高 | Next.js / Nuxt | 数据库 + 对象存储 + 队列 | 多用户、图片生成、历史版本管理 |

建议先使用本仓库的静态原型验证流程，再逐步接入后端和真实模型。
