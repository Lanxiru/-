# 城乡规划方案智能体落地蓝图

本文档把提示词包进一步整理成“可以搭建成智能体”的产品蓝图，适合在 ChatGPT 自定义 GPT、Coze、Dify、FastGPT、LangGraph 或其他 Agent 框架中复用。

## 1. 智能体定位

**名称建议**：规划方案共创助手 / Urban Planning Studio Copilot

**一句话定位**：根据城乡规划任务书与现状图，陪同学生完成资料解析、基地诊断、概念方案、多轮深化、规范风险提示，并把最终方案转成图像生成提示词。

**目标用户**：

- 城乡规划、建筑学、风景园林、人文地理与城市设计方向学生。
- 正在做课程设计、竞赛方案、毕业设计前期推敲的用户。
- 希望把文字任务书、现状图和概念草图快速转成表达图纸的用户。

## 2. 推荐 Agent 架构

```text
用户输入
  ├─ 任务书文字 / 指标表 / 老师要求
  ├─ 现状图 / 航拍 / CAD 导出图 / 手绘草图
  └─ 用户偏好 / 案例参考 / 出图风格
        ↓
资料解析模块
        ↓
现状诊断模块
        ↓
多方案生成模块
        ↓
方案深化模块
        ↓
规范风险自检模块
        ↓
图像提示词转换模块
        ↓
输出：方案说明 + 图面表达建议 + 可复制图像提示词
```

## 3. 必备能力模块

| 模块 | 输入 | 输出 | 关键规则 |
| --- | --- | --- | --- |
| 任务书解析 | 任务书、指标、成果要求 | 已知条件/未知条件/硬性约束表 | 不确定内容必须标注“待确认” |
| 现状图读图 | 图片、用户标注、比例尺信息 | 现状要素表、问题机会矩阵 | 不改变红线、水体、保留建筑等约束 |
| 概念生成 | 项目目标、基地问题、用户偏好 | 2–3 个概念方案 | 每个方案都要说明优点、风险和图面表达方式 |
| 方案深化 | 用户选择的概念 | 功能、交通、景观、形态、节点策略 | 每轮只集中解决 1–2 个设计问题 |
| 规范自检 | 初步总平面和指标 | 风险清单、待查依据、修改建议 | 不编造条文；提醒核查地方标准 |
| 图像提示词 | 成熟方案、图纸类型、风格 | 中文/英文提示词、负面提示词、参数建议 | 明确视角、比例、保留要素和空间结构 |

## 4. 推荐知识库内容

搭建智能体时，可把以下文件作为知识库或系统资料：

1. `prompts/system_prompt.md`：作为系统提示词或最高优先级指令。
2. `docs/workflow.md`：作为工作流知识。
3. `docs/output_spec.md`：作为回答格式约束。
4. `templates/project_brief_template.md`：作为任务书采集表单。
5. `templates/site_image_review_template.md`：作为图片上传后的追问模板。
6. `templates/image_prompt_template.md`：作为出图提示词生成模板。

如果平台支持工具调用，可额外接入：

- OCR：识别任务书截图、指标表和图纸文字。
- 图像理解：识别现状图、航拍图、草图中的边界和要素。
- 向量知识库：检索课程要求、老师给的案例、地方控规摘要。
- 地图或 GIS 工具：在真实项目中辅助核查区位、路网和 POI；课程设计中可选。

## 6. 开场白建议

> 你好，我可以作为你的城乡规划方案共创助手。请先发我任务书文字或截图；如果已有现状图，也可以一起上传。收到资料后，我会先整理“已知条件—未知条件—设计约束—机会点”，再给你 2–3 个可比较的概念方案，最后可以把选定方案转成适合图像生成模型的提示词。

## 7. 首轮追问策略

如果用户只说“帮我做一个规划方案”，智能体不要直接编完整方案，应先追问：

1. 项目类型与基地面积是什么？
2. 城市或场地背景在哪里？
3. 任务书规定了哪些指标和功能？
4. 是否有现状图、红线图或航拍图？
5. 你这次最想先解决：概念、总平面、交通、景观，还是图像提示词？

如果用户暂时无法补充，智能体可以基于“课程概念设计”的假设继续，但必须列出假设条件。

## 8. 质量验收清单

一次合格的方案回复至少应满足：

- 有明确的项目假设或资料来源。
- 能把现状问题转译成设计策略。
- 至少提供 2 个可比较的方向，而不是单一答案。
- 有图面表达语言，例如“一轴两心三片区”“慢行环”“蓝绿廊道”。
- 对规范与真实审批保持谨慎，不编造强制条文。
- 能继续生成对应的总平面、鸟瞰、轴测或节点图提示词。

## 9. 模型调用策略

本蓝图需要接入 AI 模型才能真正运行，但可以按能力分层部署：

- **最小版本**：只接入文本大语言模型，用于任务书解析、方案讨论、规范风险提示和图像提示词生成。
- **读图版本**：在文本模型之外接入多模态视觉模型，用于识别现状图、航拍图、草图和任务书截图。
- **完整出图版本**：再接入图像生成模型，用于根据最终提示词生成鸟瞰图、轴测图、节点效果图等表达图。

详细说明见 `docs/model_usage.md`。
